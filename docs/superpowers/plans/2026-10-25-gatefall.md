# Gatefall Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a real Unity project with the first complete endless-defense loop.

**Architecture:** Pure C# simulation owns waves, collision, gates and upgrades.
Unity runtime builds procedural world geometry, pools visual actors, and displays safe-area uGUI.
An editor initializer creates a playable scene and mobile build entry points.

**Tech Stack:** Unity 6000.3.27f1, C#, built-in renderer, uGUI, .NET 8 console specifications.

**Spec:** docs/superpowers/specs/2026-10-25-gatefall-design.md

## Global Constraints

- Target Android and iOS with portrait orientation; no network services or paid assets.
- Turkish player-facing copy. Work-in-progress name Gatefall.
- Core code has no Unity dependency; no extra packages for logic tests.
- Bound projectiles to 240 and enemies to 64; gate amplification applies once per shot.
- Prototype only: no signing credentials, payments or publishing.

## Review Focus

- A fast shot must collide with enemies and gates even when crossing between frames.
- Pause, backgrounding and upgrade selection must stop damage and spawning.
- Retry must reset run state without retaining enemies, buffs or score.
- Extreme multipliers and long runs must respect finite object caps and score bounds.
- Safe-area UI and pointer capture must prevent menu taps from moving the cannon.

**Interfaces:** `GameSession.Start(int seed)`, `Advance(float dt)`, `Move(float x)`,
`SetPaused(bool)`, `ChooseUpgrade(int)`. Read-only collection views and events consumed by renderer.

- [ ] Write specifications for start/retry, movement clamping, pause, boss scheduling,

- [ ] Implement rules and rerun the complete suite until green.
